# 14 SOURCE TRACEABILITY

## Purpose
Every external dataset, algorithm, framework and important implementation decision must be traceable.

## Dataset register

| ID | Dataset | Provider | Source | Status | Use |
|---|---|---|---|---|---|
| D-DEMO | DEMO-CITY-v2 | Generated by this repository | `src/backend/healthcare_gis/demo.py` | Synthetic, no external license | Runnable workflow and executed integration test |

No external road, hospital, health-demand or population dataset has been imported by this repository. The interface requests OpenStreetMap basemap tiles and shows provider attribution; it does not treat these tiles as analytical source data. An operator must register any later external dataset, its provider, source URL, license, retrieval date and version before reporting real-world results.

## Model register

Model versions, training data hash, feature schema, algorithm, hyperparameters, metrics and creation timestamp are stored in the `models` collection and under `MODEL_STORAGE`. `doc/16-EVALUATION-RESULTS.md` contains metrics from an executed synthetic test.

## Decision log
Document:
- why XGBoost was selected;
- why MongoDB GeoJSON and 2dsphere are used, and their limits for road routing and polygon operations;
- why Genetic Algorithm is used;
- assumptions;
- limitations.

## Academic integrity
Do not fabricate:
- dataset statistics
- model metrics
- accuracy
- population counts
- optimization savings
- external references

All final reported values must come from executed experiments.
